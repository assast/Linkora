## Why

当前只有 MarkSpace V3 浏览器本地原型，无法提供真实身份认证、服务端隐私控制、数据库持久化和多设备访问。需要在保留原型紧凑视觉与三页面交互的基础上，建设可通过容器镜像交付的前后端分离书签系统。

## What Changes

- 建立 React + TypeScript + Vite 前端与 NestJS + TypeScript 后端，使用 PostgreSQL 持久化数据。
- 采用已确认的“单所有者 + 访客只读”模式：访客读取普通内容，所有者登录后统一查看、管理普通与私密内容；通过部署初始化所有者账号。
- 实现多级分类及父级调整、书签增删改查、分类后代筛选、关键词与标签筛选、星标、排序和服务端分页。
- 在服务端统一计算分类与书签的继承私密状态，覆盖详情、列表、首页、搜索、标签、统计及导出；可能公开内容的修改须先预览并确认。
- 以 `MarkSpace-V3-直接预览.html` 为视觉依据实现导航首页、书签管理、新增/编辑三类页面，保留紧凑列表、小卡片、主题、移动端分类抽屉和五种外部搜索引擎。
- 实现当前页多选与批量移动、标签添加/移除/替换、添加/取消星标、私密设置、JSON 导出和确认后删除；写操作采用事务。
- 使用 Git 管理源码，通过 CI 检查、构建并发布前端和后端 Docker 镜像；提供 `web + api` 的 Docker Compose 部署，连接 NC 上现有 PostgreSQL，并提供数据库迁移及备份恢复说明。
- Git 平台暂按 GitHub Actions + GHCR 设计，这是尚待确认的交付假设；实际仓库地址与镜像命名在接入时配置。

一期边界：默认确认后永久删除，回收站留待后续变更；浏览器 HTML/V3 数据导入、自动网页元数据抓取、多用户注册、浏览器扩展与 AI 能力不属于本次交付。上述边界用于收敛建设方案中阶段与验收口径不一致的部分。

## Capabilities

### New Capabilities

- `single-owner-access`：单所有者初始化、登录会话、退出与访客只读访问。
- `content-visibility`：显式与继承私密状态、服务端读取边界、可见性变化确认及前端私密缓存清理。
- `category-tree`：递归分类树、分类增删改、调整父级、防环和授权后代计数。
- `bookmark-library`：书签资料维护、标签、搜索筛选、稳定排序、分页和所有者访问记录。
- `bookmark-batch-operations`：当前页选择、操作预览、事务式批量更新、删除及 JSON 导出。
- `bookmark-web-experience`：V3 风格三页面、导航搜索、响应式交互与偏好持久化。
- `container-delivery`：Git 版本管理、CI 镜像发布、Compose 运行、迁移和运维验证。

### Modified Capabilities

无，当前 `openspec/specs/` 尚无已有能力规格。

## Impact

- 新增前端、后端、数据库模型与迁移、自动化验证、容器与流水线配置；现有 HTML 和建设方案保留为参考资料。
- 新增 `/api/v1` 下的身份、分类、书签、批量预览与操作、首页和偏好接口，使用同域代理与 Cookie 会话。
- 引入 React、NestJS、PostgreSQL、Prisma、TanStack Query 以及紧凑界面所需的 UI 依赖，具体取舍见设计文档。
- 新增两个应用镜像，复用 NC 现有 PostgreSQL，为项目建立独立账号、应用库和测试库。CI 发布需要目标代码仓库及镜像仓库配置；生产入口需要 HTTPS。
- 原型的 `localStorage` 数据不会自动迁入服务端；本次从空数据库启动，既有真实数据迁移须另行确定。
