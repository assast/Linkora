## ADDED Requirements

### Requirement: Linkora 品牌与源码仓库入口
前端 SHALL 在运行界面、页面标题、登录及欢迎文案使用 Linkora 品牌，并在顶栏提供带有可见“项目源码”文字的 GitHub 仓库链接，指向 `https://github.com/assast/Linkora`。链接 SHALL 在新标签页安全打开，桌面与移动端均可使用，不能仅以图标表达入口用途。

#### Scenario: 访客打开源码仓库
- **WHEN** 访客在桌面或移动端点击顶栏的 GitHub 仓库入口
- **THEN** 新标签页打开指定仓库，原页面保持当前浏览状态且不授予外部页面 opener 访问

### Requirement: 三类页面延续 V3 视觉基准
前端 SHALL 提供导航首页、书签管理、新增/编辑三类核心页面，以参考 HTML 的布局和密度为基准，使用约 240px 桌面侧栏、49px 列表行高、偏紫主色与轻边框，默认紧凑列表并提供小卡片视图。

#### Scenario: 桌面打开管理页
- **WHEN** 用户在 1440×900 桌面视口打开书签管理
- **THEN** 左侧显示分类树，右侧显示搜索和紧凑书签列表，条目包含图标、标题/域名及当前宽度允许的分类、标签和操作信息

### Requirement: 首页聚合常用、最近与授权统计
首页 SHALL 展示最多 10 个星标快捷入口、最新 7 条收藏和当前身份的统计；快捷入口按访问次数优先并使用稳定字段补足顺序。所有内容 MUST 来自授权后的服务端数据，空库不得插入演示收藏。

#### Scenario: 所有者与访客分别打开首页
- **WHEN** 同一数据库含普通与私密书签，所有者和访客分别打开首页
- **THEN** 所有者看到全部授权内容，访客只看到公开内容，私密数量不从访客 API 返回

#### Scenario: 没有星标或没有收藏
- **WHEN** 当前身份没有星标或可见收藏
- **THEN** 对应区域显示清楚的空状态及适合当前身份的操作引导，不伪造快捷入口或统计

### Requirement: 五种可信外部搜索入口
前端 SHALL 提供 Google、Bing、百度、DuckDuckGo、GitHub 切换，用预定义可信模板编码查询词，并在新标签页打开结果；GitHub 默认搜索仓库。访客 SHALL 可以使用此功能。

#### Scenario: GitHub 搜索含特殊字符
- **WHEN** 用户选择 GitHub 并提交包含空格、中文、`&` 和 `/` 的查询词
- **THEN** 新标签页打开 GitHub 仓库搜索，解码后的查询词与输入一致，特殊字符不改变查询参数结构

#### Scenario: 空搜索
- **WHEN** 用户没有输入有效关键词而提交搜索
- **THEN** 前端不打开结果页并提示输入关键词

### Requirement: 管理页选择范围明确
前端 SHALL 支持单项选择、全选当前页、取消选择与批量工具栏，明确展示已选数量。切换分页、每页数量、排序、筛选、分类或身份时 MUST 清空选择；视图切换可以保留同一页的选择，不提供跨页全选。

#### Scenario: 全选当前页后切页
- **WHEN** 当前页显示 50 条、总结果 120 条，所有者全选后进入下一页
- **THEN** 初始只选中该页 50 条，切页后选择清空，不暗中选中其他页记录

#### Scenario: 访客进入管理页
- **WHEN** 访客查看书签管理
- **THEN** 可以搜索、筛选、切换视图和打开普通书签，不能使用编辑与批量写入；管理入口要求登录

### Requirement: 新增和编辑共用一致表单
前端 SHALL 为新增与编辑提供一致的字段与校验，保存后进入或保留编辑页并显示成功反馈。继承私密 MUST 明确显示且不能通过单项开关绕过，表单不得混淆继承状态和显式标志。

#### Scenario: 编辑继承私密书签
- **WHEN** 所有者打开私密分类下、自身显式私密为 false 的书签
- **THEN** 表单显示继承保护，保存其他资料不把自身显式私密误写为 true，也不能使书签公开

#### Scenario: 保存失败
- **WHEN** 表单保存遇到字段错误或网络失败
- **THEN** 表单保留输入并显示可理解的错误，成功状态不得提前出现

### Requirement: 偏好按身份持久化
系统 SHALL 持久化主题、默认引擎、默认视图和分类展开状态。所有者偏好存服务端，访客偏好仅存本浏览器；登录后使用账号偏好，退出后不得向访客保留私密分类状态。

#### Scenario: 所有者跨设备恢复偏好
- **WHEN** 所有者保存深色主题、小卡片视图和默认搜索引擎，再从另一设备登录
- **THEN** 前端恢复该账号已保存的偏好

#### Scenario: 访客刷新
- **WHEN** 访客修改主题或引擎后刷新同一浏览器
- **THEN** 恢复访客本地偏好，不调用已认证的偏好写接口

### Requirement: 窄屏与键盘保留核心操作
前端 SHALL 在小于等于 720px 时提供抽屉分类栏，隐藏次要列但保留搜索、打开书签和所有者批量操作；核心交互 SHALL 可通过键盘使用，弹层具有焦点管理与关闭能力。

#### Scenario: 移动端整理书签
- **WHEN** 所有者在 390×844 视口打开分类抽屉、筛选并选择书签执行批量操作
- **THEN** 页面不横向溢出，主要内容与操作可访问，抽屉可正常关闭

#### Scenario: 键盘搜索与弹层关闭
- **WHEN** 用户使用 Ctrl/Cmd+K 后输入搜索词，或在弹层按 Escape
- **THEN** 搜索框获得焦点并可使用，弹层按其交互规则关闭并恢复合理焦点

### Requirement: 请求状态和操作反馈真实
前端 SHALL 区分加载、空结果、错误和成功状态，对批量预览失效引导重新确认；书签操作按钮不得误触发网站跳转。

#### Scenario: 批量请求返回过期预览
- **WHEN** 服务端返回 409 要求重新预览
- **THEN** 前端不显示成功或静默重提危险操作，而是刷新影响信息并请求再次确认
