## ADDED Requirements

### Requirement: 有效私密状态按祖先动态继承
系统 SHALL 将分类有效私密定义为自身或任一祖先的显式私密，将书签有效私密定义为自身显式私密或所属分类有效私密。系统 MUST 分别保留显式标志和继承结果，普通子项不能绕过私密祖先。

#### Scenario: 普通子项位于私密祖先之下
- **WHEN** 根分类私密，后代分类和其中书签自身的私密标志均为 false
- **THEN** 所有后代及其书签仍有效私密，访客不可读取

#### Scenario: 显式私密移到普通分类
- **WHEN** 自身私密标志为 true 的书签移入普通分类
- **THEN** 书签保持私密，原始标志不被移动操作清除

#### Scenario: 仅继承私密的内容移出私密祖先
- **WHEN** 自身私密标志为 false 的分类或书签移至普通范围并完成公开变化确认
- **THEN** 系统重新计算其后代的有效状态，各项目原有显式私密标志保持不变

### Requirement: 所有读取面先应用授权
系统 SHALL 在搜索、统计、标签聚合、排序和分页之前过滤无权内容。分类树、书签列表、详情、首页、分类计数、标签选项和导出 MUST 遵守同一套可见性规则。

#### Scenario: 混合数据的访客读取
- **WHEN** 系统有公开书签、显式私密书签、继承私密书签以及只被私密书签使用的标签，访客读取各页面或 API
- **THEN** 返回结果、总数、分类计数和标签选项仅来自公开内容，不返回私密标题、URL、备注、分类名、图标地址或私密数量

#### Scenario: 所有者统一查看
- **WHEN** 所有者登录后查看分类、列表、首页或执行搜索
- **THEN** 普通和私密内容在同一数据范围中展示，不要求额外解锁

### Requirement: 私密直达请求不暴露存在性
系统 SHALL 对访客请求的私密分类、私密书签与不存在的同类 ID 返回相同的 404 语义，且不得允许请求参数扩大读取权限。

#### Scenario: 访客猜测私密 ID
- **WHEN** 访客直接请求私密分类或私密书签，或对其设置筛选和分页参数
- **THEN** 服务端不返回该项目内容或可推断其数量的信息，不能依赖前端隐藏完成保护

### Requirement: 公开变化须预览并明确确认
系统 SHALL 为可能使已有分类或书签从私密变为公开的编辑提供只读影响预览，包含受影响数量与内容修订号。实际提交 MUST 明确确认公开变化并重新校验预览依据。

#### Scenario: 缺少公开确认
- **WHEN** 分类调整父级、取消私密或移动书签会使已有内容变为公开，但请求未携带所需确认
- **THEN** 系统拒绝写入并提供需要确认的影响信息，原可见性保持不变

#### Scenario: 预览已失效
- **WHEN** 所有者预览后又发生内容修改，再提交原预览修订号
- **THEN** 系统返回 409，不应用变更，要求刷新影响范围并再次确认

#### Scenario: 有效确认后提交
- **WHEN** 所有者确认当前预览中的公开变化，且内容修订号未改变
- **THEN** 系统原子地应用变更，后续查询和统计立即使用新的可见性

### Requirement: 身份变化清理前端私密数据
前端 SHALL 在退出、收到认证失败或重新检查身份发现会话过期时，取消旧身份请求并清理私密查询缓存、选择、编辑状态和可见内容；私密响应 MUST 不进入公共缓存或访客持久化存储。

#### Scenario: 退出后旧请求延迟返回
- **WHEN** 所有者退出后，一个退出前发出的私密请求才返回
- **THEN** 返回结果不能重新填入访客界面或缓存，页面只展示访客可见内容

#### Scenario: 页面重新获焦发现会话过期
- **WHEN** 页面重新获焦后身份检查返回访客
- **THEN** 前端清除所有者作用域数据和选择，并重新加载公开内容
