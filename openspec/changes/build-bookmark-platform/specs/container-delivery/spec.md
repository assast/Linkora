## ADDED Requirements

### Requirement: 指定 Git 远端与 agent 管理技能
项目 SHALL 将本地 Git 的 `origin` 设置为 `https://github.com/assast/Linkora`，并在 `skill/linkora-management` 提供中文服务管理技能、API 会话客户端和运维参考。技能 SHALL 支持通过已授权 API 管理内容，保留继承私密、变更预览和修订号规则，不包含正式凭据。

#### Scenario: agent 使用已搭建服务
- **WHEN** agent 读取技能并获得目标站点与所有者凭据
- **THEN** 可以复用站点隔离的会话执行查询及授权操作，写入携带 Origin 与 CSRF，不通过直接修改数据库绕过业务规则

#### Scenario: 仅配置仓库地址
- **WHEN** 用户要求设置 Git 远端但尚未要求实际推送或部署
- **THEN** 本地 origin 指向指定地址，文档明确镜像地址，不据此触发推送、发布或 NC 部署

### Requirement: 工程通过 Git 管理且可复现构建
项目 SHALL 将前端、后端、锁文件、数据库迁移、容器配置和工作流纳入同一 Git 仓库，并提供统一的检查与构建命令。实际凭据、数据库备份和构建产物 MUST 排除在版本管理之外。

#### Scenario: 干净检出后构建
- **WHEN** CI 或开发者在干净环境检出指定提交并按锁文件安装依赖
- **THEN** 可以执行前后端检查、测试和生产构建，不依赖作者机器上的未提交文件

### Requirement: 前后端各自生成运行镜像
项目 SHALL 为 React 前端和 NestJS 后端提供独立的多阶段 Docker 构建。前端镜像 MUST 支持 SPA 路由与同域 API 代理；后端镜像 MUST 包含生产运行、数据库部署迁移和所有者初始化所需命令，并声明支持的目标平台。

#### Scenario: 镜像运行后直达编辑路由
- **WHEN** 部署已构建的镜像，浏览器直接访问前端的书签编辑路由
- **THEN** Web 服务返回 SPA，由应用按身份处理访问，API 请求通过同域代理到 NestJS

#### Scenario: 镜像独立于源码运行
- **WHEN** 服务器只有镜像和部署配置，没有项目源码或 Node.js 开发环境
- **THEN** 可以运行应用、执行部署迁移与初始化，不需要在服务器重新编译源码

### Requirement: Compose 两个应用服务连接 NC 外部数据库
项目 SHALL 提供 `web`、`api` 两个服务的 Compose 配置，连接 NC 现有 PostgreSQL 16。应用与测试 MUST 使用隔离的数据库和账号，不新建或重启共享 PG 服务，不修改其他业务数据库。Web/API SHALL 使用相同提交或发布版本的镜像，连接信息通过部署环境传入。

#### Scenario: 应用重启与数据库重连
- **WHEN** 所有者创建分类及普通/私密书签后重启应用，并重新连接 NC PG
- **THEN** 账号、分类、标签、书签及私密规则保持不变，NC 其他业务服务不受影响

#### Scenario: 拉取配对版本
- **WHEN** 部署人员指定同一应用版本并拉取 Web/API 镜像
- **THEN** 两个服务均对应该版本，并连接已配置的 NC 专用数据库

### Requirement: 首次部署先迁移后提供就绪服务
系统 SHALL 在 PG 就绪后执行版本化迁移，迁移成功后再让 API 提供就绪状态。所有者通过部署命令初始化，生产部署 MUST 提供 HTTPS 入口和与其相符的会话配置。

#### Scenario: 空数据库首次启动
- **WHEN** 使用空 PG 数据目录部署并执行初始化流程
- **THEN** 迁移创建结构，部署命令创建唯一所有者，登录和公开读取可正常使用

#### Scenario: 迁移失败
- **WHEN** 数据库迁移失败
- **THEN** 部署流程明确失败，API 不报告已就绪，不继续以未匹配的结构处理内容请求

### Requirement: CI 对拉取请求执行验证但不发布
项目 SHALL 默认提供 GitHub Actions 工作流，运行 lint、类型检查、前后端测试、真实 PG 集成测试、生产构建与 Docker 构建检查。拉取请求 MUST 不发布镜像，也不需要容器仓库写凭据。

#### Scenario: 拉取请求验证失败
- **WHEN** 拉取请求中的任何必需检查失败
- **THEN** CI 显示失败，不生成发布结果，不向镜像仓库推送标签

### Requirement: 主分支与版本标签发布可追溯镜像
在 GitHub/GHCR 默认假设下，主分支提交 SHALL 在所有检查通过后发布带 `sha-<commit>` 标签的 Web/API 镜像；有效的 `vX.Y.Z` 发布标签 SHALL 发布同版本镜像，并仅在稳定发布时更新 `latest`。两个镜像 MUST 标记相同源码提交，工作流 MUST 构建触发事件对应的提交。

#### Scenario: 主分支发布
- **WHEN** 主分支提交通过全部检查和镜像构建
- **THEN** GHCR 出现配对的 `<repository>-web` 与 `<repository>-api` 提交标签，可追溯到该次 Git 提交

#### Scenario: 发布版本
- **WHEN** 位于允许发布分支上的提交被标记为 `v0.1.0` 并通过检查
- **THEN** 两个镜像均发布 `v0.1.0` 和对应提交标签，标签所指内容来自被标记提交

### Requirement: 镜像推送与拉取使用受限凭据
工作流 SHALL 使用平台提供的令牌和所需的最小发布权限推送镜像，部署端 SHALL 使用公开读取或仅有拉取权限的凭据。镜像与工作流日志 MUST 不包含部署密码、实际数据库数据或长期仓库凭据。

#### Scenario: 私有镜像部署
- **WHEN** 镜像仓库为私有，部署端配置了有效只读凭据
- **THEN** 可以拉取指定 Web/API 镜像，不需要获得代码或镜像写入权限

### Requirement: 提供备份恢复与应用回退步骤
项目 SHALL 文档化并验证 PG 备份恢复、迁移顺序、镜像版本选择和应用回退。回退 MUST 区分兼容当前结构的应用镜像回退与需要停止写入后恢复数据库的情况，不能声称替换镜像会自动回滚数据库。

#### Scenario: 数据库备份恢复验收
- **WHEN** 测试库包含多级分类、标签、普通及私密书签，执行备份后恢复到空测试数据库
- **THEN** 数据、引用和有效私密结果与备份时一致，所有者可以登录

#### Scenario: 兼容数据库的镜像回退
- **WHEN** 将 Web/API 切回已验证兼容当前数据库的前一配对版本
- **THEN** 应用可重新提供服务，现有数据库内容保持完整
