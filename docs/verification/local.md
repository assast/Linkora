# 本地验证记录

迁移后的本地实例使用 `pnpm dev -- --no-watch` 连接正式应用库。下文 `dev:verify` 为隔离测试环境的验收记录；实际业务迁移的凭据、源快照和核验报告保存在 Git 忽略的 `.cache/` 私有目录。

## 环境与范围

- Node.js 24.22.2、pnpm 10.20.0、NC PostgreSQL 16.14。
- 本地前端 `http://127.0.0.1:5173`，NestJS API `http://127.0.0.1:3000`。
- 验证服务通过 `pnpm dev:verify` 直接启动，连接专用 `linkora_test`；测试脚本拒绝使用不以 `_test` 结尾的数据库。
- 浏览器使用隔离上下文与临时书签记录，不操作应用数据库或 NC 其他业务库。
- 按用户最新要求，本机不执行 Docker 构建/运行，Git 打包后的镜像在 NC 验证。

## 压力验证

`pnpm test:benchmark` 在独立测试库的单个事务中临时建立 5,000 条混合私密书签和四级分类。验证所有者共 5,000 项、访客仅 2,667 项、分类后代范围与分页不重复，响应只返回当前页 50 条。

事务完成后回滚，并再次检查临时记录数量为零。结果见 [benchmark.json](benchmark.json)。记录时间包含本地与 NC 的网络往返；NC 容器内的运行结果在后续阶段记录。

## 本轮修正与限制

- 调整静态批量预览路由与动态书签路由的顺序，批量请求不再被 UUID 参数校验提前拒绝。
- 跨页 Ctrl/Cmd+K 在列表挂载后聚焦；在列表内使用快捷键保留已有筛选。
- 退出后的旧异步响应不能重新写入访客界面；继承私密显示状态不写成显式私密。
- 本地验证采用构建后直接运行，避免本机文件监听数量限制。
- 批量预览明确区分总影响数量与前 10 条摘要。
